# データソース

「日本は何のエネルギーに頼ってきたか」探索ダッシュボードのための、データソースとデータ層の設計。
調査日: 2026-10-02。シート名・行・年範囲は公式 xlsx を openpyxl で読んで確認済み。

## 1. 結論

一次ソースは資源エネルギー庁「総合エネルギー統計」の **時系列表（参考表）**。
2024年度確報（2026-04-14 公表）。総合エネルギー統計は単年度のエネルギーバランス表が本体で、時系列で見るために公式がまとめたのがこの表。

- 掲載ページ: https://www.enecho.meti.go.jp/statistics/total_energy/results.html
- ファイル: https://www.enecho.meti.go.jp/statistics/total_energy/xls/stte/stte_jikeiretu2024fykaku.xlsx

出典表記: 資源エネルギー庁「総合エネルギー統計」時系列表（参考表）。

e-Stat（政府統計コード `00551010`）には年度別のバランス表と結果概要 PDF だけが載り、時系列表は無い。

### 取得

enecho.meti.go.jp は AWS WAF の JavaScript チャレンジを返すため、curl では Excel を受け取れないことがある。
`npm run fetch` は取得を試み、受け取ったものが xlsx（先頭 `PK`）でなければ手順を表示して止まる。そのときはブラウザでダウンロードして `data/raw/` に置く。

### 改訂

公表のたびに 1990 年度まで遡って改訂される（2026-04-14 も 1990 年度まで遡及）。
年度を足すときは差分ではなく、新しい xlsx から全系列を作り直す。

## 2. シートと採用

各シートは同じ形で、行が項目、列 D–AL が 1990–2024 年度（35時点）。B 列が「年度」の行がブロックの見出しで、その1行上の AL 列に単位がある。

| シート | ブロック（単位） | 採用 |
| --- | --- | --- |
| `1.一次エネルギー国内供給` | PJ / 原油換算万kl / 構成比 / 前年度比 | PJ（配信）、構成比（照合） |
| `2.最終消費(エネルギー源別)` | 同上 | 同上 |
| `3.最終消費(部門別)` | 同上 | 同上 |
| `4.電源構成(発電量）` | 億kWh / 構成比 / 前年度比 | 億kWh（配信）、構成比（照合） |
| `5.電源構成(投入量）` | — | 不採用。発電量と物語が重なる |
| `6.CO2排出量` | — | 不採用。別の問い |
| `7.エネルギー自給率` | — | 不採用。別の問い |

原油換算万kl は PJ の定数倍の換算なので配信しない。前年度比は配信値から求まるので配信しない。
構成比は画面側で「内訳の和」に対する比として計算する。build 時に公式の構成比ブロックと突き合わせ、ずれたら失敗させる。

### 供給 — `1.一次エネルギー国内供給`

石炭・石油・天然ガス・都市ガス・再生可能（水力除く）・水力（揚水除く）・未活用・原子力 の7項目と合計。1990–2024 年度。

### 消費 — `2.最終消費(エネルギー源別)`

石炭・石油・天然ガス・都市ガス・再生可能・未活用・電力・熱 の7項目と合計。1990–2024 年度。
未活用は 1990 年代に 0（前年度比は N/A）。

### 部門 — `3.最終消費(部門別)`

親子の2階層。親（企業・事業所他／運輸）は子の和なので配信の積み上げには使わず、`groups` として持つ。

| 親 | 子（配信） |
| --- | --- |
| 企業・事業所他 | 農林水産鉱業建設、製造業、業務他 |
| 家庭 | 家庭 |
| 運輸 | 旅客、貨物 |

子の行は先頭に全角スペースが入る。1990–2024 年度。

### 電源 — `4.電源構成(発電量）`

原子力・石炭・天然ガス・石油等・水力・太陽光・風力・地熱・バイオマス の9項目と合計。
ゼロエミッション電源は小計なので配信しない。
表注: 「2009年度以前は電力調査統計の自家発電において、バイオマスが別掲されていないため、電源構成は2010年度から掲載する。」1990–2009 年度の列は空欄で、配信は **2010–2024 年度**。

## 3. 配信データ

`public/data/{view}.json`。ビューごとに1ファイル。行優先の cube（`src/app/data/cube.ts`）。

| ファイル | 次元 | 単位 |
| --- | --- | --- |
| `supply.json` | item(7) × year(35) | PJ |
| `final.json` | item(7) × year(35) | PJ |
| `sector.json` | item(6) × year(35) | PJ |
| `power.json` | item(9) × year(15) | 億kWh |

```json
{
  "unit": "PJ",
  "items": [{ "code": "coal", "label": "石炭", "level": 1 }],
  "groups": [{ "code": "business", "label": "企業・事業所他", "level": 0 }],
  "dims": [{ "name": "item", "codes": ["coal"] }, { "name": "year", "codes": ["1990"] }],
  "measures": { "value": [3317.772] }
}
```

- `items` の順は公式シートの行順。`groups` は部門のみ。
- 値は小数3桁に丸める。欠測は無い（ある年度はすべて埋まっている）。

## 4. 検証

`npm run data`（`scripts/build_data.py`）が失敗させる条件:

- 内訳の和が公式の「合計」行と一致しない（相対誤差 1e-6 超）
- 内訳から計算した構成比が公式の構成比ブロックと一致しない（絶対誤差 1e-6 超）
- 期待した項目ラベルがシートに無い

`npm run verify`（`scripts/verify.ts`）は配信 JSON を読んで確かめる:

- 年度が連続し、最終年度が 2024
- 供給が7項目、電源の開始が 2010 年度
- 値がすべて非負で欠測が無い
- 2024年度の一次エネルギー国内供給の合計が 17,461 PJ 前後、発電量の合計が 9,911 億kWh 前後（シート上の合計行）
